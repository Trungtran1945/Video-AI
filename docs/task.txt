The system automatically organizes these resources into a multi-track timeline and renders a complete video.

## 3. NEW USER WORKFLOW

Design the following workflow:

### Step 1: Create Project

Allow users to configure:
- Project name.
- Aspect ratio: 16:9, 9:16, 1:1.
- Resolution.
- FPS.
- Output format (MP4).
- Optional default background.

### Step 2: Upload Media Assets

Create a Media Library inside the project.

Support:

**Background**
- Upload background image.
- Upload background video.
- Set background duration and fit mode.

**Images**
- Upload multiple images simultaneously.
- Preview thumbnails.
- Reorder images.
- Delete or replace images.
- Add images to timeline.

**Audio**
- Upload background music.
- Upload sound effects.
- Upload voiceover audio.
- Preview audio and display duration.

**Voiceover**
- Upload an existing voice recording.
- Alternatively, enter text and generate speech using existing TTS providers.
- Allow voice provider and voice selection.
- Reuse existing TTS infrastructure.

**Text**
- Allow users to manually enter text.
- Allow translated image text to be added as text overlays.

All uploaded assets must belong to the authenticated user and project.

Use secure storage keys and existing storage conventions.

Do not store media binaries directly in SQLite.

### Step 3: Image OCR & Translation

Every image should have an optional `Dịch thuật` action.

Workflow:

`Image → OCR → Original Text → Translation → Editable Text → Add to Timeline`

Requirements:

1. Detect text inside the selected image.
2. Display recognized original text.
3. Allow target-language selection.
4. Translate using the existing Translation Provider architecture.
5. Display the translation in an editable text field.
6. Allow users to correct the translation.
7. Provide an `Add to Video` action.
8. Create an independent text overlay clip on the timeline.

OCR and translation must be separate operations.

Prefer existing local OCR capabilities such as Tesseract when appropriate, reducing unnecessary external API calls.

Implement caching:
- Reuse OCR results when image content and OCR configuration are unchanged.
- Reuse translation results when source text, target language and translation configuration are unchanged.
- Do not call AI repeatedly when displaying existing results.
- Do not translate automatically unless the user requests it.

Never modify the original image when adding translated text.

### Step 4: Automatic Timeline Generation

This is the core functionality.

Build a real multi-track timeline.

Required tracks:

1. Video / Background
2. Images
3. Voiceover
4. Background Music / Sound Effects
5. Text / Subtitles

Each track must support appropriate operations:
- Add clips.
- Remove clips.
- Reorder clips.
- Adjust start time.
- Adjust duration.
- Select and mute/unmute tracks.
- Adjust audio volume.
- Preview content.
- Update clip properties.

Automatic arrangement rules:

**Background**
- Starts at 0.
- Covers the complete output duration.
- Supports image or video backgrounds.

**Images**
- Follow the user's selected order.
- If narration segments exist, distribute images across the corresponding narration segments.
- If only one voiceover audio file exists without timestamps, distribute images sequentially across its duration.
- If no voiceover exists, use a configurable default image duration.
- Avoid unintended gaps or overlaps.

**Voiceover**
- Starts at the configured position, default 0.
- Use the actual probed audio duration.
- Support uploaded audio and generated TTS audio.

**Background Music**
- Starts at 0 by default.
- Support looping or trimming to the final video duration.
- Allow volume adjustment.
- Support fade-in and fade-out.
- Implement optional audio ducking when voiceover is present.

**Text**
- Place text overlays at their configured start/end timestamps.
- Support independent editing.
- Keep text rendering separate from original image assets.

Provide an `Auto Arrange` button that generates a valid timeline from the selected resources.

Provide a `Reset Timeline` action with confirmation.

Do not require users to manually create every clip.

Extend the underlying model to support generic media tracks.

Support:

- Multiple audio clips.
- Text overlays.
- Clip selection.
- Drag and drop.
- Trim handles.
- Timeline zoom.
- Playhead synchronization.
- Playback controls.
- Clip property editing.
- Track mute/unmute.
- Audio volume.
- Snapping.

Do not break existing TRANSLATE_DUB timeline functionality.

The preview must reflect the actual timeline state, not static sample data.

### Step 6: Preview and Rendering

Create a preview player that displays the composition.

The rendering engine must combine:

- Background.
- Images and video clips.
- Image transitions.
- Text overlays.
- Subtitles.
- Voiceover.
- Background music.
- Sound effects.

Use FFmpeg.

Reuse existing functions from `mediaService.js` where applicable.

Add new functions only when required.

Requirements:
- Normalize output dimensions.
- Normalize frame rate.
- Handle audio/video duration correctly.
- Avoid unexpected black frames.
- Avoid missing media references.
- Mix voiceover and background music correctly.
- Support optional audio ducking.
- Render text with appropriate fonts and Vietnamese Unicode support.
- Export valid MP4 using H.264/AAC.
- Generate output thumbnail.
- Save output metadata.

Do not run heavy rendering operations directly inside HTTP requests.

Use BullMQ and existing worker infrastructure.

Send rendering progress through existing SSE infrastructure.

Support cancellation, retry and error reporting.
