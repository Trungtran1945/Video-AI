# TASK-040

## Title
Fix cancelProjectUseCase deleting persistent project directory instead of temp directory

## Type
bug

## Priority
critical

## Autonomy
auto

## Evidence
[`cancelProjectUseCase.js:44-50`](file:///D:/E/Video_AI/backend/src/usecases/cancelProjectUseCase.js#L44-L50): When cancelling an active or pending project, `cancelProjectUseCase` attempts to remove temporary files:
```javascript
// Clean up temp files in storage/tmp/{projectId}
const tmpDir = path.join(projectDir(projectId))
try {
  if (fs.existsSync(tmpDir)) {
    fs.rmSync(tmpDir, { recursive: true, force: true })
  }
} catch (_) {}
```
`projectDir(projectId)` resolves to `storage/projects/{projectId}`, which contains permanent project artifacts (source assets, transcripts, SRT subtitles, and rendered outputs). Using `projectDir(projectId)` completely destroys all saved project files on cancellation, making subsequent pipeline regenerations fail. Meanwhile, the actual temporary directory `tmpDirOf(projectId)` (`storage/tmp/{projectId}`) is leaked and never cleaned.

## Affected Areas
- `backend/src/usecases/cancelProjectUseCase.js`

## Expected Outcome
Import `tmpDirOf` from `../pipeline/context.js`. Update `cancelProjectUseCase.js` to target `tmpDirOf(projectId)` instead of `projectDir(projectId)`:
```javascript
import { projectDir, tmpDirOf } from '../pipeline/context.js'
...
const tmpDir = tmpDirOf(projectId)
```
Persistent project files in `storage/projects/{projectId}` remain intact upon cancellation, while scratch files in `storage/tmp/{projectId}` are cleaned up.

## Constraints
Do not alter project cancellation state transitions or notification dispatching.

## Suggested Verification
`cd backend && node -e "import('./src/usecases/cancelProjectUseCase.js')"`

[`summaryAnalyze.js:9-24`](file:///D:/E/Video_AI/backend/src/pipeline/stages/summaryAnalyze.js#L9-L24): `selectKeyScenes(rows)` implements adaptive temporal scene sampling for the `SUMMARY` pipeline:
- If `rows.length <= 24`, it returns a shallow clone of `rows`.

2. Preservation of all scenes when input length is `<= 24`.
3. Correct bucket count and bounds (`k` between 8 and 40) when input length is `> 24` (e.g. 50 scenes, 300 scenes).
4. Longest-duration scene selection within each bucket partition.
