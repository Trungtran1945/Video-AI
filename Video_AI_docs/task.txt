### P0 — Process-local single-flight có thể cross-project

backend/src/lib/callProvider.js hiện dùng:

inFlightProviderCalls

với key:

provider + type + inputHash

Key không chứa:

projectId
userId
ownership boundary.

Trong backend/src/pipeline/stages/dubTtsAlign.js, fn() truyền vào callProvider tạo audio tại:

projectDir(project.id)/audio_segments/...

Scenario nguy hiểm:

Project A:
same TTS key
→ provider call
→ result chứa /project-A/audio.mp3

Project B đồng thời:
same TTS key
→ await cùng Promise
→ nhận result chứa /project-A/audio.mp3

Như vậy single-flight có thể tạo cross-project artifact reuse ngay cả khi persistent provider_cache chưa tồn tại.

### P0 — Persistent provider cache cũng trộn computation và artifact ownership

audioPath

Không được giải quyết bằng cách đơn giản thêm projectId vào cache key nếu vẫn muốn shared deterministic computation.

project-owned artifact.

4. THAY ĐỔI BẮT BUỘC
==================================================

### 4.1. Tách provider computation khỏi artifact ownership

Thiết kế:

canonical provider request
→ shared deterministic computation
→ safe content/result/immutable artifact identity
→ project-specific materialization
→ project-owned artifact.

Không để shared provider result chứa project-local audioPath.

Nếu provider hiện tại bắt buộc outPath:

- không lưu project-local path vào shared cache;
- materialize riêng cho caller;
- hoặc cache MISS nếu không thể chứng minh ownership.

Ưu tiên không dùng projectId làm cách duy nhất để phá single-flight.

--------------------------------------------------

### 4.2. Sửa single-flight

Không cho:

Project A
→ Promise chứa /project-A/...

được Project B await và sử dụng trực tiếp.

Ưu tiên:

single-flight chỉ share provider computation/content.

Mỗi caller tạo/materialize artifact riêng dưới project storage của mình.

Bổ sung regression test concurrent:

Project A + Project B
same provider
same input.

Expected:

- không có project-A path trả cho B;
- mỗi project có artifact hợp lệ;
- nếu computation được dedupe thì artifact materialization vẫn tách biệt.

--------------------------------------------------

### 4.3. Sửa persistent provider cache

provider_cache không được lưu project-local audioPath như shared result.

Legacy cache có local audioPath nhưng không có ownership proof:

CACHE MISS.

Không xóa toàn bộ cache database một cách mù quáng.

Có thể invalidate unsafe cache entry khi phát hiện.

--------------------------------------------------

### 4.4. Artifact ownership

Project-owned artifact phải được xác định bằng:

projectId + artifactId/storageKey.

Không dùng filesystem path làm authorization proof.

Nếu shared immutable artifact được hỗ trợ:

- content-addressed;
- immutable;
- explicit reference;
- explicit authorization;
- cleanup không được xóa artifact còn được project khác reference.

--------------------------------------------------

### 4.5. ZeroTTS admission control

Không để ThreadingHTTPServer tạo unlimited waiting threads.

Thiết kế:

HTTP
→ bounded admission
→ bounded queue
→ inference workers.

Hoặc ít nhất thêm:

ZEROTTS_MAX_INFLIGHT_REQUESTS

để reject request trước khi chờ model semaphore.

Khi capacity đầy:

HTTP 429 hoặc 503.

Structured code:

SERVER_BUSY
hoặc QUEUE_FULL.

Không để hàng trăm request giữ thread chờ 120 giây.

--------------------------------------------------

### 4.6. Request body limit

Thêm:

ZEROTTS_MAX_BODY_BYTES

và:

ZEROTTS_MAX_TEXT_CHARS.

Kiểm tra Content-Length trước read().

Nếu vượt:

HTTP 413.

Text quá dài:

HTTP 400/413.

Nếu Content-Length không có:

dùng bounded read hoặc reject rõ ràng.

Không đọc unlimited body.

--------------------------------------------------

### 4.7. Resource config validation

Validate:

ZEROTTS_THREADS >= 1
ZEROTTS_CONCURRENCY >= 1
ZEROTTS_MAX_INFLIGHT_REQUESTS >= 1

và giới hạn upper bound hợp lý.

Invalid config:

fail-fast.

Document:

HTTP admission
queue
inference concurrency
ONNX threads.

--------------------------------------------------

### 4.8. Output root security

Thêm:

ZEROTTS_OUTPUT_ROOT.

Mọi output phải nằm dưới root.

Reject:

../ traversal
absolute path ngoài root
symlink escape
arbitrary parent directory.

Nếu có thể, loại bỏ arbitrary out_path khỏi public API.

Service tự tạo safe filename/artifact ID.

--------------------------------------------------

### 4.9. MP3 phải là MP3 thật

Nếu requested MP3:

ZeroTTS raw WAV
→ FFmpeg
→ MP3
→ ffprobe validation.

Nếu FFmpeg unavailable:

FAIL.

Nếu conversion failure:

FAIL.

Không:

WAV bytes → .mp3.

Không:

except Exception: pass.

Node và Python đều phải enforce invariant.

--------------------------------------------------

### 4.10. Speed contract

ZeroTTS native model không hỗ trợ speed trực tiếp nếu implementation hiện tại không truyền speed vào model.

Architecture:

ZeroTTS raw audio
→ FFmpeg tempo fitting
→ final audio.

Cache identity phải phản ánh final output semantics.

Không để API contract làm caller hiểu rằng ZeroTTS native synthesis đã áp dụng speed.

Không phá native speed của Edge/OpenAI.

5. TIÊU CHÍ NGHIỆM THU
==================================================

### Cache isolation

Concurrent Project A + Project B cùng TTS input:

- không project nào nhận local path của project kia;
- shared computation chỉ được dùng nếu artifact ownership vẫn an toàn;
- mỗi project có artifact hợp lệ.

Legacy unsafe cache:

→ CACHE MISS.

### Single-flight

Hai project đồng thời cùng TTS request:

→ không cross-project local audioPath.

### Backpressure

ZEROTTS_CONCURRENCY=1.

Gửi nhiều request đồng thời.

Expected:

- active request bounded;
- queue bounded;
- excess request trả 429/503;
- không tạo unlimited waiting threads;
- request tiếp theo thành công sau khi capacity giải phóng.

### Request limit

Body > MAX_BODY_BYTES:

→ 413.

Text > MAX_TEXT_CHARS:

→ 400/413.

### Filesystem

Valid output dưới output root:

→ success.

Traversal/outside root/symlink escape:

→ reject.

### MP3

MP3 output:

→ ffprobe xác nhận codec/container đúng.

FFmpeg fail:

→ provider failure.

### Timeout

Client timeout:

→ PROVIDER_TIMEOUT.

Không permanent semaphore/queue leak.

Request tiếp theo:

→ success.

### Failover

Duplicate candidate:

→ không consume attempt budget sai.

All transient:

→ retryable.

All quota:

→ không blind retry.

Mixed:

→ structured classification.

### Docker

docker compose config --quiet

PASS.

Nếu Docker daemon khả dụng:

docker compose up -d --build

Verify:

redis
zerotts
api
web

và:

API → ZeroTTS → model → audio.
